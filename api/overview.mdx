AGRO-JUTIAPA exposes a lightweight REST API that powers the open-access agrometeorological and financial viability platform for white maize sowing in Calderas, San José Acatempa, Jutiapa, Guatemala. The API requires no authentication and is available both on the local multithreaded Python server (port 8000) and as Vercel Serverless Functions on your production deployment.

## Base URLs

| Environment | Base URL |
|-------------|----------|
| Local (Python server) | `http://localhost:8000` |
| Vercel deployment | `https://your-project.vercel.app` |

Start the local server with:

```bash
python server.py 8000
```

## Authentication

No authentication is required. All endpoints are open access — consistent with the platform's design principle of universal, unrestricted access for smallholder producers in the Guatemalan Dry Corridor.

## CORS

Every endpoint sets the following response header, allowing cross-origin requests from any browser or client:

```
Access-Control-Allow-Origin: *
```

All endpoints also handle `OPTIONS` preflight requests, responding with `200 OK` and the full set of allowed methods and headers before any actual data transfer occurs.

## Rate Limits

No rate limits are enforced at the application level. However, the server does impose a **10 KB maximum request body size** on `POST /api/analyze` to prevent denial-of-service. Requests exceeding this limit receive an HTTP `413` response.

## Endpoints Summary

| Method | Path | Description |
|--------|------|-------------|
| `POST` | `/api/analyze` | Full agrometeorological + financial analysis: ERA5 ingestion, FAO-56 water balance, XGBoost inference, traffic-light verdict, parcel geometry, sowing density, and P&L projection |
| `GET` | `/api/maga-price` | Real-time wholesale corn price scraped from the official MAGA Guatemala portal (La Terminal market), with 10-minute in-memory cache and Q 235.00 fallback |

## Error Format

All error responses from both endpoints share the same JSON envelope:

```json
{
  "success": false,
  "error": "Human-readable description of the error."
}
```

`POST /api/analyze` also sets an optional `validation_error` flag on `400` responses to distinguish input validation failures from internal errors:

```json
{
  "success": false,
  "error": "UBICACIÓN NO PERMITIDA: Este sistema está diseñado, calibrado y habilitado ÚNICAMENTE para Calderas...",
  "validation_error": true
}
```

### HTTP Status Codes

| Code | Meaning |
|------|---------|
| `200` | Success — response body contains the requested data |
| `400` | Validation error — invalid input parameter (includes `validation_error: true`) |
| `404` | Not found — unrecognized path |
| `405` | Method not allowed — wrong HTTP method for the endpoint (Vercel deployment only; the local Python server does not return 405) |
| `413` | Request body too large — exceeds the 10 KB limit on `POST /api/analyze` |
| `500` | Internal server error — pipeline execution or scraping failure |
